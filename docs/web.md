# Веб-редактор (`mapcan app`, `mapcan serve`)

Редактор карты в браузере: дерево карты, формы, интерактивная битовая карта кадра,
проверка на лету, предпросмотр и выгрузка документов, сравнение версий.
Сохраняет YAML **с комментариями, порядком ключей и форматированием** — в `git diff`
видны только реально изменённые строки.

На рабочем месте редактор удобнее запускать как приложение — ярлыком mapcan из установщика
или командой `mapcan app` (нужен `mapcan[desktop]`, иначе откроется браузер):

```sh
mapcan app                               # отдельное окно, стартовый экран
mapcan app my-map.yaml                   # сразу открыть карту
mapcan app --browser                     # то же, но во вкладке браузера
```

* **Один экземпляр.** Повторный запуск или двойной щелчок по `.yaml` не запускает второй
  редактор, а открывает файл в уже открытом окне и выводит его на передний план. Если в текущей
  карте есть несохранённые правки, редактор спросит, что с ними делать.
* **Порт** — 8765, а если он занят — любой свободный. Окно открывается, когда сервер готов.
* **Закрытие окна** с несохранёнными правками требует подтверждения.
* **Обновления.** Раз в сутки редактор проверяет [последний релиз](https://github.com/ordu1453/mapcan/releases/latest)
  и показывает плашку со ссылкой на установщик. «Скрыть» убирает её до следующей версии.
  Отключить проверку: переменная окружения `MAPCAN_NO_UPDATE_CHECK=1`.
* Настройки окна, тема и выбранный шаблон PDF хранятся в `~/.mapcan/webview/`, журнал ошибок
  оконной версии — в `~/.mapcan/mapcan.log`.

`mapcan serve` — тот же редактор во вкладке браузера, для сервера и разработки фронтенда:

```sh
mapcan serve                             # стартовый экран: создать или открыть карту
mapcan serve my-map.yaml                 # сразу открыть карту (http://127.0.0.1:8765/)
mapcan serve maps/                       # стартовый экран, рабочая папка — maps/
mapcan serve my-map.yaml --readonly      # только просмотр
mapcan serve my-map.yaml --port 9000 --no-browser
```

Перезапускать сервер для другой карты не нужно: **Файл → Новая карта / Открыть / Сохранить как /
Закрыть** работают прямо в браузере. Диалог файлов позволяет ходить по любым папкам и дискам, ввести
путь вручную и открыть один из недавних файлов. Если в текущей карте есть несохранённые правки,
редактор предложит сохранить их перед переключением.

Версия mapcan показана в верхней панели рядом с названием и на стартовом экране.

## Профиль автора

При первом запуске редактор попросит указать **имя** и (необязательно) **GitHub** — имя пользователя
или ссылку на профиль. Профиль хранится на компьютере в `~/.mapcan/config.json` (каталог можно сменить
переменной окружения `MAPCAN_CONFIG_DIR`); там же список недавних файлов. Изменить профиль — кнопка с
инициалами в правом верхнем углу.

Профиль используется, чтобы было видно, кто какие изменения внёс:

* **Новая карта** создаётся с `document.author` и первой записью истории от вашего имени.
* **Сравнить версии → Добавить в историю** подписывает запись именем и GitHub:

  ```yaml
  history:
    - version: 1.0.1
      date: 2026-10-06
      author: Иван Петров
      github: ivan-p
      changes:
        - "0x196 imd_state: добавлен сигнал reserve (биты 24–31)"
  ```

* Автор со ссылкой на GitHub выводится в листе «Изменения» Excel, в приложении PDF, в Markdown и HTML.

Редактор рассчитан на одного пользователя на своей машине: по умолчанию слушает только
`127.0.0.1`, аутентификации нет. С `--host 0.0.0.0` он станет доступен по сети — mapcan
предупредит об этом при запуске.

## Интерфейс

| Область | Что делает |
|---|---|
| **Дерево** (слева) | Документ → шины → устройства → кадры → сигналы → флаги, SDO-обмены. Рядом с кадром — CAN ID, с сигналом — занятые биты. Точка — ошибка/предупреждение в узле, кольцо — в дочерних узлах. |
| **Поиск** | По имени, описанию, CAN ID (`0x196` или `406`). Несколько слов — все должны совпасть. |
| **Свойства** | Форма выбранного узла. Значение применяется по Enter или при уходе из поля. Сообщения проверки показываются под полем. `en` — добавить английский перевод текста. Кружок «?» у подписи поля — справка: что это за настройка, зачем нужна и какие значения допустимы (при наведении; по клику закрепляется, Esc — закрыть). |
| **Раскладка кадра** | Битовая карта: строки — байты, колонки — биты 7…0. Подписи — имена сигналов и флагов битовых полей. |
| **Кадры** | Список кадров на странице шины или устройства; ✕ в строке удаляет кадр. Новый кадр («+ Кадр») добавляется в этот список, выбранный узел не меняется. |
| **Значения / Флаги** | Таблицы enum и битовых полей: значение (dec или `0x…`), имя, описание. «+ Флаг» добавляет строку в таблицу, не уходя со страницы сигнала. |
| **Проверка** (снизу) | Те же правила, что `mapcan validate`. Клик по сообщению — переход к узлу (во вкладке YAML — к строке). |
| **YAML** | Правка файла целиком; номера строк с ошибками подсвечены. Применение — Ctrl+Enter. |
| **Экспорт** | Документы (PDF, HTML, Markdown, Excel) и форматы для разработки (DBC, C, Python) — из текущего состояния, в том числе несохранённого. Щелчок по документу открывает предпросмотр, где для PDF выбирается шаблон: mapcan, ЕСКД, ЕСПД, ГОСТ 7.32 ([docs/templates.md](templates.md)); ↓ справа — сразу скачать. |
| **Оформление и реквизиты** | В свойствах документа: логотип (загрузка файла), обозначение, литера, организация, город, подписи основной надписи, «УТВЕРЖДАЮ», «СОГЛАСОВАНО». |
| **Сравнить версии** | Diff текущей карты с версией из git (HEAD, тег, коммит) или с загруженным файлом: изменения кадров, сигналов, значений, флагов. «Добавить в историю» записывает changelog в `document.history` и обновляет версию. |
| **Git** | Ветка, состояние файла карты и число неотправленных коммитов. «Закоммитить…» коммитит только карту и её логотип (можно сразу поставить тег версии), «Поставить тег…», pull (`--ff-only`, карта перечитывается) и push (первый push задаёт upstream). Если папка не в репозитории — «Создать репозиторий здесь»; если нет remote — «Опубликовать на GitHub…» через [GitHub CLI](https://cli.github.com) (`gh repo create --source . --push`, нужен `gh auth login`). Для github.com push и pull используют учётные данные `gh`, если он установлен. В режиме только для чтения меню скрыто. |

### Битовая карта

* **Новый сигнал** — протяните мышью по свободным битам. Сигнал получит позицию
  little-endian от младшего выделенного бита до старшего.
* **Сдвиг** — перетащите сигнал.
* **Длина** — у выбранного little-endian сигнала на младшем и старшем битах есть ручки;
  тяните за них. Big-endian сигналы можно сдвигать, длину задайте в форме.
* **Пересечения** подсвечиваются красной штриховкой сразу во время перетаскивания.
  У мультиплексированных кадров есть переключатель значения селектора: «все» — показать
  все наборы (взаимоисключающие сигналы на одних битах не считаются пересечением).
* Позиция записывается в самом читаемом виде: `byte`/`bit`/`byte_length`, если сигнал
  выровнен по байтам, иначе `start_bit`/`bit_length`. Если сигнал был записан через
  `start_bit`, запись сохраняется.

### Горячие клавиши

| Клавиши | Действие |
|---|---|
| Ctrl+S | Сохранить |
| Ctrl+Shift+S | Сохранить как |
| Ctrl+O | Открыть |
| Ctrl+Z / Ctrl+Y (Ctrl+Shift+Z) | Отменить / повторить (вне полей ввода) |
| Delete | Удалить выбранный узел дерева (без подтверждения — отменяется Ctrl+Z; вне полей ввода) |
| Ctrl+Enter | Применить правку во вкладке YAML |
| Esc | Закрыть диалог, прервать перетаскивание |

## Как сохраняется форматирование

Браузер не присылает YAML целиком: каждое действие — это операция над путём в документе
(`set`, `insert`, `remove`, `move`, `rename_key`, `set_layout`). Сервер применяет её к
round-trip дереву ruamel.yaml, а затем переносит изменения на исходный текст построчно:
нетронутые фрагменты — включая комментарии, пустые строки, кавычки, hex-запись чисел и
ручные переносы во flow-словарях `{...}` — остаются байт-в-байт прежними. Окончания строк
(LF/CRLF) сохраняются.

Если файл изменили в другой программе (например, в VS Code или через `git pull`),
появится баннер: перечитать файл с диска или оставить свою версию. Сохранение поверх
чужих изменений требует подтверждения.

## API

Интерфейс работает поверх HTTP API, его можно использовать из скриптов;
описание — на `http://127.0.0.1:8765/api/docs`.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/meta` | Версия mapcan, профиль, недавние файлы, открыта ли карта |
| GET/PUT | `/api/user` | Профиль автора `{name, github}` |
| GET | `/api/update` | Новая версия на GitHub Releases `{current, latest, newer, url, installer}` (только `mapcan app` и локальный `serve`) |
| POST | `/api/instance/activate` | `{token, path}` — повторный запуск передаёт файл работающему экземпляру (токен — в `~/.mapcan/instance.json`) |
| GET | `/api/fs/list?dir=` | Папки и YAML-файлы для диалога |
| POST | `/api/file/open`, `/api/file/new`, `/api/file/save_as`, `/api/file/close` | Работа с файлами; 409 `unsaved` — есть несохранённые правки (`force: true` — продолжить) |
| GET | `/api/state` | Текст, данные, вычисленная раскладка, диагностика |
| POST | `/api/ops` | `{"ops": [...]}` — атомарное применение операций |
| POST | `/api/text` | Заменить текст YAML |
| POST | `/api/undo`, `/api/redo` | История правок |
| POST | `/api/save` | `{"force": false}`; 409 — файл изменён на диске |
| POST | `/api/reload` | Перечитать файл |
| GET | `/api/export/{xlsx,pdf,md,html,dbc,c,py}` | Документ из текущего состояния (`?download=true`, для PDF `?template=gost-2.105`) |
| GET | `/api/templates` | Встроенные шаблоны PDF |
| GET/POST | `/api/logo` | Логотип карты: получить / загрузить (сохраняется рядом с картой) |
| GET | `/api/git/revs` | Теги и коммиты с файлом карты |
| POST | `/api/diff/git`, `/api/diff/upload` | Сравнение с версией из git или с файлом |
| GET | `/api/git/status` | Ветка, upstream, remote, расхождение, состояние файла, последний коммит |
| POST | `/api/git/init`, `/api/git/commit`, `/api/git/tag`, `/api/git/push`, `/api/git/pull` | Операции git (карта должна быть сохранена) |
| GET/POST | `/api/gh/status`, `/api/gh/create` | Вход в GitHub CLI; создание репозитория на GitHub с push |
| WS | `/ws` | События `state` (правка в другой вкладке) и `file-changed` |

## Разработка фронтенда

Исходники — в [web/](../web) (Vue 3 + TypeScript + Vite). Собранный бандл лежит в
`src/mapcan/web/static/` и входит в пакет, поэтому пользователям Node.js не нужен.

```sh
mapcan serve my-map.yaml --no-browser     # API на :8765
cd web
npm ci
npm run dev                               # http://localhost:5173, горячая перезагрузка
npm run build                             # проверка типов + сборка в src/mapcan/web/static
```

После изменений во `web/src` пересоберите бандл и закоммитьте `src/mapcan/web/static` —
CI проверяет, что бандл соответствует исходникам.
